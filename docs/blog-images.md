# 博客图片与 Typora

Typora 能显示图片，只能说明本机能找到它。发布时还需要提交图片文件，并使用网站可处理的路径。

## 推荐操作

在 Typora 的「偏好设置 → 图像」中，将插入图片设置为复制到文章旁的相对目录，例如 `./${filename}.assets`，并优先使用相对路径。不同版本的选项名称可能略有不同。

例如：

```text
src/content/blog/my-post.md
src/content/blog/my-post.assets/screenshot.png
```

文章里写：

```md
![编辑器界面](./my-post.assets/screenshot.png)
```

提交文章时一起提交 `.assets` 图片目录。Typora 显示原图；网站在开发或构建时自动生成压缩版本，并修改渲染结果中的图片地址，Markdown 和原图保持不变。`npm run build` 会在部署工作流上传 `dist` 前完成压缩。

## 截图压缩标准

- 输出格式：静态 WebP，保留透明通道。
- 文件上限：100KiB（102,400 字节，约 100KB），小图不会刻意增大到该大小。
- 初始宽度：最多 1600px，不放大小图，保持比例。
- 编码质量：依次尝试 85、75、65、55；仍超限时，逐步缩小宽度，最低缩到 640px。
- 达到最低宽度和质量仍超限时，构建报错，提示拆分截图，避免继续把文字压糊。长截图建议按内容分段。
- 原图保留。生成文件位于 `public/_blog-images`，不提交 Git；构建产物会包含这些文件。

此标准适用于博客 Markdown 的相对路径图片，包括引用式图片。`C:\...`、`file://...` 和网络共享路径会导致构建报错。远程 HTTP/HTTPS 图片和网站根路径图片保持原地址，不执行压缩；远程图片的可用性取决于源站。直接写 HTML `<img>` 不经过这套压缩，应改用 Markdown 图片语法。动画请使用独立的资源发布方式，不使用截图压缩流程。

压缩发生在网站构建阶段，而不是 Typora 粘贴时，所以仓库仍保存原始截图，网站上传的是压缩后的版本。
